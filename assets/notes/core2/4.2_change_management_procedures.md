## 📌 Overview

Change management ensures that modifications to systems, applications, configurations, or infrastructure occur in a controlled, documented, and predictable manner. Core 2 requires understanding how to plan, document, approve, implement, and validate changes while minimizing risk and disruption.

---

## 📝 Documented Business Processes

### Rollback Plan
* Defines how to revert changes if issues occur.
* Must be:
  * Tested
  * Documented
  * Ready before implementation
* Example: Restore previous configuration or revert to last known-good backup.

### Backup Plan
* Ensures data and configurations are preserved before changes.
* Includes:
  * Full system backups
  * Configuration snapshots
  * Database backups

### Sandbox Testing
* Testing changes in an isolated environment.
* Prevents production impact.
* Used for:
  * Software updates
  * Configuration changes
  * New deployments

### Responsible Staff Members
* Identifies:
  * Who performs the change
  * Who approves the change
  * Who monitors the change
* Ensures accountability and clear ownership.

## 🔄 Change Management Components

### Request Forms
* Formal documentation initiating the change.
* Includes:
  * Requester info
  * Description of change
  * Business justification

### Purpose of the Change
* Explains why the change is needed.
* Examples:
  * Security patching
  * Performance improvements
  * Compliance requirements

### Scope of the Change
* Defines:
  * Systems affected
  * Departments impacted
  * Expected downtime
* Helps determine risk and required approvals.

### Change Type

#### Standard Change
* Pre-approved, low-risk, repeatable.
* Examples:
  * Routine updates
  * Scheduled maintenance

#### Normal Change
* Requires full review and approval.
* Medium risk.
* Not urgent.

#### Emergency Change
* Needed immediately to fix critical issues.
* Examples:
  * Outage recovery
  * Security breach mitigation
* May bypass normal approval steps.

### Date and Time of Change

#### Change Freeze
* Period where no changes are allowed.
* Common during:
  * Holidays
  * Major business events
  * End-of-quarter processing

#### Maintenance Windows
* Scheduled times for performing changes.
* Minimizes business disruption.

### Affected Systems / Impact
* Identifies:
  * Servers
  * Applications
  * Network components
  * Users impacted
* Helps plan communication and downtime.

### Risk Analysis

#### Risk Level
* Low, medium, high.
* Considers:
  * Probability of failure
  * Impact of failure
  * Complexity of change

### Change Board Approvals
* Change Advisory Board (CAB) reviews:
  * Risk
  * Scope
  * Business justification
* Approves or denies changes.

### Implementation
* Executing the change according to documented steps.
* Includes:
  * Pre-checks
  * Deployment
  * Validation
  * Post-change monitoring

### Peer Review
* Another technician reviews:
  * Documentation
  * Steps
  * Risks
* Ensures accuracy and reduces mistakes.

### End-User Acceptance
* Confirms change meets user needs.
* Often part of:
  * Software updates
  * UI changes
  * Workflow modifications

## ⚡ Key Vocabulary

Change Freeze  
: Period where changes are prohibited to avoid disruption.

CAB  
: Change Advisory Board responsible for approving changes.

Rollback Plan  
: Steps to revert a change if issues occur.

Sandbox  
: Isolated environment for testing changes safely.

## ⚡ Exam Tips & Pitfalls

!!! exam "Exam Tip: Emergency Changes"
    Emergency changes skip normal approval steps but **still require documentation** afterward.

!!! danger "Common Pitfall: No Rollback Plan"
    Never implement a change without a rollback plan — CompTIA emphasizes this heavily.

!!! tip "Remember: Maintenance Windows"
    If a scenario mentions minimizing user impact, schedule changes during **maintenance windows**.

!!! warning "Watch Out: Scope Creep"
    Changes must stay within documented scope — expanding scope increases risk and requires new approval.

!!! example "Scenario: Failed Update"
    **Scenario:** A system update causes application failures.  
    **Solution:** Execute the **rollback plan**, restore backups, and document the incident for CAB review.
