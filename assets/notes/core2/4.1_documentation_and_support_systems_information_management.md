## 📌 Overview

Accurate documentation and structured support systems ensure efficient troubleshooting, consistent service delivery, and proper asset tracking. Core 2 requires understanding ticketing workflows, asset management practices, and the types of documents used in IT operations.

---

## 🎫 Ticketing Systems

Ticketing systems track issues from initial report to final resolution. Good documentation ensures clarity, accountability, and proper escalation.

### User Information
* Name  
* Department  
* Contact details  
* Role (helps determine urgency)

### Device Information
* Device type (laptop, desktop, mobile)  
* Asset tag / serial number  
* OS version  
* Network location  

### Description of Issues
* Clear, concise summary of the problem  
* Include symptoms, error messages, and user observations  

### Categories
* Hardware  
* Software  
* Network  
* Security  
* Access/permissions  
* Application-specific  

### Severity
* **Low:** Minor inconvenience  
* **Medium:** Impacts productivity  
* **High:** Critical system failure  
* **Urgent:** Outage affecting multiple users  

### Escalation Levels
* Tier 1 → Basic troubleshooting  
* Tier 2 → Advanced support  
* Tier 3 → Specialists or engineers  
* Vendor escalation → External support  

### Clear, Concise Written Communication

#### Issue Description
* Summarize the problem without unnecessary detail.  
* Include relevant logs or screenshots.

#### Progress Notes
* Document each troubleshooting step.  
* Include timestamps and actions taken.

#### Issue Resolution
* Describe the fix clearly.  
* Note root cause and preventive steps.  
* Close the ticket with user confirmation.

## 🏷 Asset Management

Asset management tracks hardware, software, and lifecycle information.

### Inventory Lists
* Catalog of all devices and equipment.  
* Includes model, serial number, purchase date, and assigned user.

### Configuration Management Database (CMDB)
* Centralized database storing:
  * Hardware details  
  * Software versions  
  * Network configurations  
  * Relationships between systems  

### Asset Tags and IDs
* Unique identifiers attached to devices.  
* Used for tracking, auditing, and support.

### Procurement Life Cycle
* Acquisition → Deployment → Maintenance → Retirement → Disposal  
* Ensures proper budgeting and replacement planning.

### Warranty and Licensing
* Tracks:
  * Warranty expiration  
  * Software license keys  
  * Subscription renewals  

### Assigned Users
* Links devices to responsible individuals.  
* Helps track usage, accountability, and support history.

## 📄 Types of Documents

### Incident Reports
* Formal documentation of security events or major outages.  
* Includes:
  * Timeline  
  * Impact  
  * Root cause  
  * Remediation  
  * Preventive measures  

### Standard Operating Procedures (SOPs)
* Step-by-step instructions for repeatable tasks.  
* Ensures consistency and compliance.

#### Software Package Custom Installation Procedure
* Defines:
  * Required settings  
  * Dependencies  
  * Post-installation checks  

### New User / Onboarding Setup Checklist
* Includes:
  * Account creation  
  * Email setup  
  * Device assignment  
  * Permissions  
  * Required software  

### User Off-Boarding Checklist
* Includes:
  * Account disablement  
  * Device return  
  * Data archiving  
  * Access removal  
  * License reassignment  

### Service-Level Agreements (SLAs)

#### Internal
* Defines expectations between departments.  
* Example: IT must respond to tickets within 4 hours.

#### External / Third-Party
* Contractual agreements with vendors.  
* Includes:
  * Response times  
  * Support availability  
  * Performance guarantees  

### Knowledge Base / Articles
* Repository of:
  * Troubleshooting guides  
  * FAQs  
  * How-to documents  
* Helps technicians resolve issues quickly.

## ⚡ Key Vocabulary

Ticket  
: A documented record of an issue from report to resolution.

CMDB  
: Database storing configuration and relationship information for IT assets.

SLA  
: Agreement defining expected service levels and response times.

Incident Report  
: Formal documentation of outages or security events.

## ⚡ Exam Tips & Pitfalls

!!! exam "Exam Tip: Ticket Quality"
    Clear, concise notes matter. CompTIA expects you to document **what you did**, **why you did it**, and **what happened**.

!!! danger "Common Pitfall: Missing Asset Tags"
    Always record asset tag numbers — they tie devices to users, warranties, and support history.

!!! tip "Remember: SOPs"
    SOPs ensure consistency. If a scenario mentions “repeatable process,” choose **SOP**.

!!! warning "Watch Out: SLAs"
    Internal SLAs govern department expectations; external SLAs govern vendor obligations.

!!! example "Scenario: Technician Hands Off a Ticket"
    **Scenario:** A Tier 1 technician escalates a ticket to Tier 2.  
    **Solution:** Ensure progress notes clearly document all steps taken so Tier 2 can continue without repeating work.
