## 📌 Overview

Scripting allows technicians to automate repetitive tasks, gather system information, deploy updates, and streamline workstation management. Core 2 requires understanding common script file types, typical use cases, and the risks associated with improper scripting.

---

## 📄 Script File Types

### .bat (Batch)
* Windows command-line scripts.
* Used for:
  * File operations  
  * Network drive mapping  
  * Running CLI tools  

### .ps1 (PowerShell)
* Advanced Windows scripting.
* Supports:
  * System administration  
  * Automation  
  * API interaction  
  * Configuration management  

### .vbs (VBScript)
* Legacy Windows scripting language.
* Used for:
  * Simple automation  
  * Windows dialog boxes  
  * Basic logic operations  

### .sh (Shell Script)
* Linux/macOS command-line scripts.
* Used for:
  * System configuration  
  * Package installation  
  * Cron automation  

### .js (JavaScript)
* Browser scripting or Node.js automation.
* Used for:
  * Web automation  
  * Form validation  
  * Server-side tasks (Node.js)  

### .py (Python)
* Cross-platform scripting language.
* Used for:
  * Data processing  
  * Automation  
  * API calls  
  * System utilities

## 🔧 Use Cases for Scripting

### Basic Automation
* Automate repetitive tasks.
* Reduce human error.

### Restarting Machines
* Scheduled reboots.
* Remote restart commands.

### Remapping Network Drives
* Automatically reconnect drives at login.
* Useful in enterprise environments.

### Installation of Applications
* Silent installs.
* Automated deployment across multiple machines.

### Automated Backups
* Scheduled file or folder backups.
* Integration with cloud or local storage.

### Gathering Information / Data
* Collect:
  * System logs  
  * Hardware info  
  * Network details  
* Useful for inventory and troubleshooting.

### Initiating Updates
* Trigger OS or application updates.
* Useful for large-scale maintenance windows.

---

## ⚠️ Other Considerations When Using Scripts

### Unintentionally Introducing Malware
* Running unknown scripts can:
  * Install malicious software  
  * Modify system files  
  * Exfiltrate data  
* Always verify script source and integrity.

### Inadvertently Changing System Settings
* Scripts can:
  * Modify registry keys  
  * Change permissions  
  * Alter network configurations  
* Test in sandbox environments before deployment.

### Browser or System Crashes Due to Mishandling Resources
* Poorly written scripts may:
  * Consume excessive CPU/RAM  
  * Create infinite loops  
  * Crash browsers or OS processes

## ⚡ Exam Tips & Pitfalls

!!! exam "Exam Tip: Script Types"
    `.bat` = Windows CMD  
    `.ps1` = PowerShell  
    `.sh` = Linux/macOS  
    `.py` = Python  

!!! danger "Common Pitfall: Running Unknown Scripts"
    Never run scripts from untrusted sources — they may contain malware.

!!! tip "Remember: Sandbox Testing"
    Always test scripts in a **sandbox** before production deployment.

!!! warning "Watch Out: Infinite Loops"
    Poor scripting logic can crash systems or browsers.

!!! example "Scenario: Automating Drive Mapping"
    **Scenario:** A technician needs network drives to reconnect automatically at login.  
    **Solution:** Use a `.bat` or `.ps1` script to map drives and place it in the startup folder or login script.
