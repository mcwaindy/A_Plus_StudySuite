## 📌 Overview

Workstation hardening reduces attack surfaces, protects data, and enforces secure user behavior. Core 2 requires understanding encryption, password policies, account management, BIOS/UEFI security, and best practices for securing devices in both SOHO and enterprise environments.

---

## 🔐 Data-at-Rest Encryption

* Protects stored data from unauthorized access.
* Common methods:
  * **BitLocker** (Windows)
  * **FileVault** (macOS)
  * **EFS** (file-level encryption)
* Prevents data theft if device is lost or stolen.

---

## 🔑 Password Considerations

### Length
* Longer passwords are more secure.
* Recommended minimum: **12–16 characters**.

### Character Types
* Use a mix of:
  * Uppercase
  * Lowercase
  * Numbers
  * Symbols

### Uniqueness
* Avoid reusing passwords across accounts.

### Complexity
* Should not contain personal info (names, birthdays).

### Expiration
* Periodic password changes may be required in some environments.
* Modern best practice: encourage strong, unique passwords rather than frequent forced changes.

---

## 🧬 BIOS/UEFI Passwords

* Prevent unauthorized access to firmware settings.
* Types:
  * **Supervisor/Admin password** — protects BIOS/UEFI configuration.
  * **User/System password** — required to boot the machine.
* Helps prevent boot‑order changes or unauthorized OS installs.

---

## 👤 End-User Best Practices

### Use Screensaver Locks
* Automatically locks workstation after inactivity.

### Log Off When Not in Use
* Prevents unauthorized access to active sessions.

### Secure/Protect Critical Hardware
* Use cable locks for laptops.
* Store devices in secure locations.

### Secure PII and Passwords
* Avoid writing passwords on sticky notes.
* Store sensitive data in encrypted locations.

### Use Password Managers
* Generates strong passwords.
* Securely stores credentials.

---

## 👥 Account Management

### Restrict User Permissions
* Apply **principle of least privilege**.
* Standard users should not have admin rights.

### Restrict Log-In Times
* Limits access to specific hours.
* Useful in business environments.

### Disable Guest Account
* Prevents anonymous access.

### Use Failed Attempts Lockout
* Locks account after repeated failed logins.
* Protects against brute-force attacks.

### Use Timeout/Screen Lock
* Automatically locks workstation after inactivity.

### Apply Account Expiration Dates
* Used for temporary employees or contractors.

---

## 🔧 Change Default Administrator Account/Password

* Rename default admin account to reduce attack visibility.
* Set a strong, unique password.
* Prevents attackers from targeting known default credentials.

---

## ⛔ Disable AutoRun

* Prevents automatic execution of media (USB, CD/DVD).
* Protects against malware spread via removable devices.

---

## 📴 Disable Unused Services

* Reduces attack surface.
* Examples:
  * Remote Desktop (if not needed)
  * FTP server
  * Telnet
  * Bluetooth (if unused)
* Fewer running services = fewer potential vulnerabilities.

---

## ⚡ Key Vocabulary

Least Privilege  
: Users receive only the access required to perform their job.

AutoRun  
: Feature that automatically launches media content; disabling prevents malware execution.

Account Lockout  
: Security control that blocks access after repeated failed login attempts.

UEFI Password  
: Firmware-level password protecting boot and configuration settings.

## ⚡ Exam Tips & Pitfalls

!!! exam "Exam Tip: Hardening Order"
    Hardening typically follows: **secure accounts → enforce passwords → enable encryption → disable unnecessary features → educate users**.

!!! danger "Common Pitfall: Leaving Guest Account Enabled"
    Guest accounts bypass identity controls — always disable them.

!!! tip "Remember: AutoRun"
    Many malware infections spread via USB drives. Disabling AutoRun is a key hardening step.

!!! warning "Watch Out: Default Admin Account"
    Attackers target default admin names. Renaming and securing this account is essential.

!!! example "Scenario: Unauthorized Access After Hours"
    **Scenario:** A workstation is accessed late at night when no employees should be present.  
    **Solution:** Implement **log-in time restrictions** and enforce **screen lock timeout**.
