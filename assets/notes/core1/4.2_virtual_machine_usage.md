## 📌 Overview

Client-side virtualization allows a single physical host machine to create and execute multiple isolated guest operating systems (Virtual Machines or VMs) simultaneously. Understanding hypervisor architectures (Type 1 vs. Type 2), hardware resource allocation, virtual networking modes, and virtual machine security controls is essential for supporting enterprise environments and testing labs.

---

## 🖥️ Hypervisor Architectures

A hypervisor (or Virtual Machine Monitor / VMM) is the software, firmware, or hardware layer that creates, manages, and executes virtual machines by abstracting physical host resources.

### Type 1 Hypervisor (Bare-Metal)
* **Architecture:** Installs and runs directly on the physical host hardware without an underlying host operating system.
* **Performance & Latency:** High performance, low overhead, and direct hardware control.
* **Target Environment:** Enterprise data centers, server virtualization, and cloud infrastructure.
* **Examples:** VMware ESXi, Microsoft Hyper-V (bare-metal installation), Proxmox VE, KVM.

### Type 2 Hypervisor (Hosted)
* **Architecture:** Installs as an application on top of an existing host operating system (e.g., Windows, macOS, Linux).
* **Performance & Latency:** Higher latency and lower efficiency because guest OS requests must pass through both the hypervisor and the host OS.
* **Target Environment:** Desktop client-side virtualization, developer testing, legacy app execution, and educational labs.
* **Examples:** Oracle VM VirtualBox, VMware Workstation / Fusion, Parallels Desktop.

## ⚙️ Resource Allocation & Hardware Requirements

Virtual machines do not possess physical components; instead, the hypervisor allocates host physical hardware to each guest VM.

### Key Resource Requirements
* **RAM (System Memory):** Every active VM requires a dedicated block of physical host RAM. If host RAM is overcommitted, the hypervisor relies heavily on host disk paging, severely degrading performance.
* **CPU / vCPUs (Virtual CPUs):** Hypervisors assign logical cores or threads (vCPUs) from the physical host CPU to guest VMs. Hardware-assisted virtualization features (**Intel VT-x** or **AMD-V**) must be enabled in the host BIOS/UEFI.
* **Storage (Virtual Disks):** Virtual machines store their entire OS, files, and state in single large file formats (e.g., `.vmdk`, `.vhdx`, `.vdi`) hosted on physical SSDs or HDDs.
* **Network Interfaces (vNICs):** Virtual Network Interface Cards emulate physical network adapters within the guest OS.

## 🌐 Virtual Networking Configurations

Hypervisors construct virtual switches to manage network communications between guest VMs, the host machine, and external networks.

| Network Mode | Communication Scope | Internet Access | Typical Use Case |
| :--- | :--- | :--- | :--- |
| **Bridged** | VM receives a unique IP address on the **physical local network**. Appears as a distinct physical machine on the network. | **Yes** (Direct local network access) | Running production servers or services requiring external accessibility |
| **NAT (Network Address Translation)** | VM shares the physical host's IP address. Hypervisor translates traffic between internal VM IP and external network. | **Yes** (Outbound traffic permitted) | Standard desktop VM usage requiring safe web browsing without exposing ports |
| **Host-Only** | VM communicates **only** with the physical host and other VMs on the same host-only network. | **No** | Isolated malware testing labs and host-to-VM file transfers |
| **Internal / Isolated** | VMs communicate **only** with other VMs on the same internal virtual switch. Host cannot access the network. | **No** | Secure multi-tier application development environments |

## 🛡️ Virtual Machine Security & Isolation

Virtualization provides software containment, but shared physical hardware introduces unique security considerations.

* **VM Isolation (Sandboxing):** Guest VMs operate within an isolated software sandbox. A crash, virus infection, or security breach inside a guest OS does not normally affect the host OS or other guest VMs.
* **VM Escape:** A critical security vulnerability where malicious code inside a guest VM breaks out of the virtualization layer to execute unauthorized commands directly on the host operating system.
* **Rogue VMs:** Unmanaged or unauthorized virtual machines created on a network that bypass enterprise security policies, monitoring, and patch management.
* **Host vs. Guest Security Requirements:** Guest VMs require full traditional security management—including independent OS patching, antivirus/anti-malware installations, and firewall rule configurations.

## ⚡ Key Vocabulary

Hypervisor
: The software, firmware, or hardware layer that creates, manages, and executes virtual machines.

Type 1 Hypervisor
: A bare-metal hypervisor that runs directly on physical server hardware without a host OS.

Type 2 Hypervisor
: A hosted hypervisor that installs and executes as an application on top of an existing operating system.

VM Escape
: An exploit where an attacker bypasses guest isolation to execute code directly on the host hypervisor or host OS.

vCPU
: Virtual CPU. A logical processing thread assigned by the hypervisor from the physical host CPU to a virtual machine.

## ⚡ Exam Tips & Pitfalls

!!! exam "Exam Tip: Enabling Hardware Virtualization in BIOS"
    If a technician attempts to launch a Virtual Machine in a Type 2 hypervisor and receives an error stating "Hardware virtualization is disabled", enter the system **BIOS/UEFI** and enable **Intel VT-x** or **AMD-V**.

!!! danger "Common Pitfall: Assuming Host Security Covers Guest VMs"
    Installing antivirus or updating security patches on the **host OS does not protect the guest VMs**! Each virtual machine runs an independent operating system and must be patched, secured, and updated separately.

!!! tip "Remember: Bridged vs. NAT"
    * **Bridged Mode:** The VM gets its own IP address from the physical local network (e.g., from the router's DHCP server).
    * **NAT Mode:** The hypervisor gives the VM a private IP address and translates traffic through the host's IP.

!!! warning "Watch Out: RAM Overcommitment"
    While CPUs can share threads easily through time-slicing, **physical RAM cannot be safely shared simultaneously**. Ensure the host PC has enough physical RAM to power the host OS plus the sum of all active guest VM allocations.

!!! example "Scenario: Safe Malware Analysis Lab"
    **Scenario:** A cybersecurity analyst needs to run and inspect a suspicious executable file without risking infection to the corporate network or the analyst's local workstation.
    
    **Solution:** Create a Virtual Machine in a Type 2 hypervisor, configure the network adapter to **Host-Only** or **Internal/Disabled**, take a **VM Snapshot**, and execute the file within the isolated VM sandbox.
