## 📌 Overview

Networking relies on standardized protocols and port numbers to allow applications across a network to establish communication, transfer files, send emails, and access resources. The CompTIA A+ exam heavily tests your ability to identify common ports, recognize their underlying transport protocol (TCP vs. UDP), and understand their primary network functions.

---

## 🔄 TCP vs. UDP Comparison

At the Transport Layer (Layer 4), networking protocols rely on either **TCP (Transmission Control Protocol)** or **UDP (User Datagram Protocol)** to transport data.

| Feature / Aspect | TCP (Transmission Control Protocol) | UDP (User Datagram Protocol) |
| :--- | :--- | :--- |
| **Connection Type** | Connection-oriented (Requires 3-way handshake) | Connectionless (No handshake) |
| **Reliability** | **Reliable:** Guarantees delivery via acknowledgments | **Unreliable:** "Best effort" delivery; no ACKs |
| **Data Flow** | Resends lost packets; maintains byte sequence order | Packets sent independently; no retransmissions |
| **Overhead & Speed** | Higher overhead; slower transmission speed | **Low overhead; extremely fast / lightweight** |
| **Common Use Cases** | Web browsing, file transfers, email, SSH | Streaming media, VoIP, DNS queries, online gaming |

## 🌐 Essential Ports & Protocols

Below is the complete catalog of core networking protocols and port numbers tested on the 220-1101 exam:

### Web & Security Services
* **HTTP (Hypertext Transfer Protocol) - TCP 80:** Transfers unencrypted web pages across the World Wide Web.
* **HTTPS (HTTP Secure) - TCP 443:** Encrypts web traffic using TLS/SSL to secure sensitive web browsing and transactions.
* **SSH (Secure Shell) - TCP 22:** Provides an encrypted remote terminal connection for secure CLI administrative access.
* **Telnet - TCP 23:** Legacy unencrypted remote terminal interface. Transmits credentials and commands in plain text (insecure).

### File Transfer & Sharing
* **FTP (File Transfer Protocol) - TCP 20/21:** Transmits files between client and server. Port 21 manages control/commands; Port 20 handles actual data transfer.
* **SMB (Server Message Block) - TCP 445:** Used by Windows operating systems for sharing files, folders, and printers across a local network.
* **AFP (Apple Filing Protocol) - TCP 548:** Legacy proprietary file sharing protocol used by macOS devices.

### Email Protocols
* **SMTP (Simple Mail Transfer Protocol) - TCP 25:** Sends email from clients to servers or transfers mail between email servers.
* **POP3 (Post Office Protocol v3) - TCP 110:** Downloads email from a server to a single local device, typically deleting it from the server afterwards.
* **IMAP (Internet Message Access Protocol) - TCP 143:** Synchronizes email across multiple devices while keeping mail stored on the central server.

### Network Infrastructure & Addressing
* **DNS (Domain Name System) - UDP/TCP 53:** Resolves human-readable domain names (e.g., `google.com`) into numerical IP addresses. Uses UDP 53 for standard queries; TCP 53 for zone transfers.
* **DHCP (Dynamic Host Configuration Protocol) - UDP 67/68:** Automatically assigns IP addresses, subnet masks, default gateways, and DNS servers to network clients. Port 67 is used by the server; Port 68 by the client.

### Management & Directory Services
* **SNMP (Simple Network Management Protocol) - UDP 161/162:** Monitors and gathers metrics from network devices (routers, switches, printers). Queries use UDP 161; automated alarm messages (Traps) use UDP 162.
* **LDAP (Lightweight Directory Access Protocol) - TCP 389:** Queries and manages directory services (such as Microsoft Active Directory) for network authentication.
* **LDAPS (LDAP Secure) - TCP 636:** Encrypts LDAP directory traffic over SSL/TLS.

### Remote Access & Legacy Networking
* **RDP (Remote Desktop Protocol) - TCP 3389:** Proprietary Microsoft protocol enabling a graphical view and remote control of a Windows desktop PC.
* **NetBIOS / NetBT - UDP 137/138, TCP 139:** Legacy Windows protocol suite for hostname resolution (137), datagram services (138), and session handling (139) over TCP/IP.

## ⚡ Key Vocabulary

TCP
: Transmission Control Protocol. Connection-oriented, reliable transport layer protocol that uses a 3-way handshake and guarantees packet delivery.

UDP
: User Datagram Protocol. Connectionless, lightweight transport layer protocol designed for speed without delivery guarantees.

Port Number
: A 16-bit numerical identifier (0–65535) used at the Transport Layer to direct network traffic to specific applications or services on a host.

Three-Way Handshake
: The process TCP uses to establish a connection (SYN $\rightarrow$ SYN-ACK $\rightarrow$ ACK) before data transfer begins.

## ⚡ Exam Tips & Pitfalls

!!! exam "Exam Tip: IMAP vs. POP3"
    Remember the crucial functional difference: **POP3** downloads mail locally and removes it from the server (one device access). **IMAP** keeps mail on the server and synchronizes changes across multiple client devices.

!!! danger "Unencrypted vs. Encrypted Alternatives"
    CompTIA heavily tests secure vs. insecure protocol pairs:
    * **HTTP (80)** $\rightarrow$ Secure with **HTTPS (443)**
    * **Telnet (23)** $\rightarrow$ Secure with **SSH (22)**
    * **LDAP (389)** $\rightarrow$ Secure with **LDAPS (636)**

!!! tip "DHCP Port Mnemonic"
    DHCP uses UDP ports **67 and 68**. Remember: "Server **67** listens, Client **68** receives."

!!! warning "Watch Out: DNS Protocol Choice"
    DNS primarily uses **UDP 53** for quick name resolution queries. However, if a DNS response exceeds 512 bytes or during **zone transfers** between DNS servers, DNS switches to **TCP 53**.

!!! example "Scenario: High-Speed Voice/Video Lag"
    **Scenario:** An organization is setting up a Voice over IP (VoIP) phone system and needs to select the optimal transport protocol. Why is UDP chosen over TCP for real-time video and voice streaming?
    
    **Solution:** UDP is connectionless and does not retransmit lost packets. In real-time voice or video, retransmitting a dropped audio packet 2 seconds late creates unacceptable lag and distortion; skipping the dropped packet entirely results in imperceptible audio drops while preserving real-time synchronization.
