## 📌 Overview

Network configuration concepts dictate how devices obtain network addresses, resolve human-readable domain names into IP addresses, isolate network traffic logically, and securely connect remote hosts over untrusted networks. Understanding DNS record types, DHCP IP allocation mechanisms, Virtual LANs (VLANs), and Virtual Private Networks (VPNs) is critical for administering modern IP networks.

---

## 🌐 Domain Name System (DNS) Record Types

DNS acts as the "phonebook of the Internet," translating human-friendly hostnames (such as `example.com`) into numerical IP addresses required for network routing.

### Core DNS Records
* **A Record (Address Record):** Maps a hostname to a 32-bit **IPv4 address** (e.g., `web.example.com` $\rightarrow$ `192.168.1.50`).
* **AAAA Record (Quad-A Record):** Maps a hostname to a 128-bit **IPv6 address** (e.g., `web.example.com` $\rightarrow$ `2001:db8::1`).
* **MX Record (Mail Exchanger):** Specifies the mail server responsible for accepting incoming email messages on behalf of a domain. MX records always point to a hostname (A or AAAA record), not directly to an IP address, and include a priority value.
* **TXT Record (Text Record):** Stores arbitrary human-readable or machine-readable text within a DNS zone. Primarily used for domain ownership verification and email security/spam management.

### Email Security & Spam Management TXT Records
* **SPF (Sender Policy Framework):** A TXT record listing all IP addresses and mail servers authorized to send email on behalf of a domain, preventing address spoofing.
* **DKIM (DomainKeys Identified Mail):** Uses public-key cryptography stored in a TXT record to digitally sign outgoing emails, ensuring messages were not altered in transit.
* **DMARC (Domain-based Message Authentication, Reporting, and Conformance):** Uses TXT records to define how a receiving mail server should handle emails that fail SPF or DKIM checks (e.g., `none`, `quarantine`, or `reject`).

## 📡 Dynamic Host Configuration Protocol (DHCP)

DHCP automatically assigns IP addresses and network configuration settings to client devices, eliminating manual static IP assignment errors.

### Core DHCP Concepts
* **Scope:** The defined range (pool) of valid IP addresses that a DHCP server is configured to assign to clients on a specific subnet, along with subnet masks, default gateways, and DNS server addresses.
* **Lease:** The temporary duration for which a client is granted permission to use an assigned IP address. Clients periodically request a lease renewal (typically at 50% of the lease time).
* **Reservation:** A permanent IP assignment configured on the DHCP server that maps a specific device's MAC address to a fixed IP address within the scope. Ensures the device always receives the same IP via DHCP (commonly used for printers, servers, and NAS devices).

### The DHCP DORA Process
When a client connects to a network, it obtains an IP address through a 4-step process:
1. **Discover (Client $\rightarrow$ Server):** Client broadcasts a request to locate available DHCP servers.
2. **Offer (Server $\rightarrow$ Client):** DHCP server responds with an offered IP address and configuration.
3. **Request (Client $\rightarrow$ Server):** Client requests the offered IP address.
4. **Acknowledge / ACK (Server $\rightarrow$ Client):** DHCP server confirms the lease assignment.

## 🔒 Virtual LANs (VLANs) & Virtual Private Networks (VPNs)

Logical network segmentation and secure remote access rely on VLANs and VPNs.

### Virtual LAN (VLAN)
* **Definition:** A logical grouping of network devices on one or more physical switches configured to act as if they are connected to an isolated Layer 2 broadcast domain.
* **Benefits:**
  * **Security:** Isolates sensitive departments (e.g., HR or Finance) from general user traffic.
  * **Traffic Management:** Limits broadcast storms by shrinking the size of broadcast domains.
* **Trunking (IEEE 802.1Q):** Enables a single physical cable between switches to carry traffic for multiple VLANs by adding a 4-byte identification tag to Ethernet frames.

### Virtual Private Network (VPN)
* **Definition:** An encrypted tunnel created over an untrusted public network (such as the Internet) to safely connect remote users or branch offices to a private internal network.
* **VPN Deployment Models:**
  * **Host-to-Site (Remote Access VPN):** An individual remote laptop uses software (VPN client) to establish an encrypted tunnel to a corporate VPN concentrator.
  * **Site-to-Site VPN:** Connects two static physical networks (e.g., Headquarters and a Branch Office) using dedicated VPN routers or firewalls. The connection is transparent to end users.

## ⚡ Key Vocabulary

A Record
: A DNS record mapping a domain name directly to an IPv4 address.

MX Record
: A DNS Mail Exchanger record specifying the mail server responsible for domain email.

DORA Process
: The 4-step DHCP handshake: Discover, Offer, Request, Acknowledge.

DHCP Reservation
: A mapping on a DHCP server that reserves a specific IP address for a device based on its MAC address.

VLAN Trunking
: Passing traffic for multiple VLANs across a single physical switch connection using 802.1Q tagging.

## ⚡ Exam Tips & Pitfalls

!!! exam "Exam Tip: DNS Record Types"
    * **A** = IPv4 address mapping
    * **AAAA** = IPv6 address mapping
    * **MX** = Mail server
    * **TXT** = Email authentication (SPF, DKIM, DMARC) and domain verification

!!! danger "Common Pitfall: Static IP vs. DHCP Reservation"
    Configuring a **Static IP** requires manual entry on the client machine itself. A **DHCP Reservation** is configured on the central DHCP server so the client remains set to "Obtain an IP address automatically" while receiving the exact same IP every time.

!!! tip "Remember: DHCP DORA Sequence"
    Remember the acronym **DORA**: **D**iscover $\rightarrow$ **O**ffer $\rightarrow$ **R**equest $\rightarrow$ **A**cknowledge.

!!! warning "Watch Out: VLAN Broadcast Isolation"
    Devices on different VLANs **cannot communicate** without a Layer 3 device (router or Layer 3 switch) to route traffic between them, even if they are plugged into the same physical switch.

!!! example "Scenario: Preventing Email Domain Spoofing"
    **Scenario:** An enterprise company discovers that malicious actors are sending phishing emails pretending to come from `@company.com`. How can the IT administrator prevent domain spoofing using DNS?
    
    **Solution:** Create DNS **TXT records** for **SPF** (listing authorized sending IP addresses), **DKIM** (providing cryptographic signatures), and **DMARC** (instructing recipient servers to reject forged mail).
